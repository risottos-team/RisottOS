RisottOS

A compact 32-bit x86 educational operating system

Architecture, boot process, protected mode, Ring 3 execution, drivers, storage, and current engineering status.

Repository: risottos-team/RisottOs

Document version: 1.0

Prepared: 20 October 2026

Primary runtime: BIOS + QEMU i386

Scope note. This document describes the repository as it exists today. Some subsystems are implemented as reusable kernel code but are not reached by the active boot path.

1. Executive overview

RisottOS is a freestanding, 32-bit x86 operating-system project intended for learning low-level boot, protected-mode execution, interrupt handling, device I/O, and the first steps toward user mode. It does not depend on an operating-system runtime or a standard C library once the kernel starts.

What happens today: the BIOS boot sector loads the kernel, the kernel initializes the interrupt and timer infrastructure, prints its startup messages, creates a small machine-code program at a fixed address, and transfers execution to Ring 3. The test program invokes int 0x80 once and then loops safely in user mode.

3. Boot and kernel startup

  1. BIOS load: the BIOS places the boot sector at 0x7C00.
  2. Relocation: the boot code copies itself to 0x0600, protecting the original location while the kernel is loaded.
  3. A20 and disk: it requests A20 enablement and uses BIOS EDD INT 13h, AH=42h to read 99 sectors from LBA 1 into physical address 0x1000.
  4. Protected mode: the bootloader loads an initial GDT, sets CR0.PE, performs a far jump, installs data segments, and sets the kernel stack to 0x90000.
  5. Kernel entry: kernel_entry.asm calls kmain().
  6. Initialization: the kernel configures the IDT, enables the page-fault gate, builds a 16 MiB identity map, rebuilds the GDT and TSS, remaps the PIC, enables interrupts, starts the PIT and ATA support, and initializes a 4 MiB heap.
  7. User-mode test: the kernel writes test instructions to 0x500000 and enters Ring 3 with iretd.
BIOS → relocate boot sector → load kernel at 0x1000 → protected mode
     → _start → kmain → IDT/GDT/TSS/PIC/PIT/ATA → Ring 3 smoke test
Hard-coded loader limit: the bootloader always reads 99 sectors and has no kernel-size metadata or bounds validation. The current kernel fits, but growth can silently make the image unsafe.

The first paging layer builds four page tables covering the first 16 MiB with identity mappings and enables the CPU paging bit. The first 4 MiB is supervisor-only; the Ring 3 image, stack, and dedicated user heap are in the user-accessible range. A page-fault gate reports the faulting address and halts the system. Syscall allocations now come from the user heap, while the kernel heap remains supervisor-only.

5. GDT, IDT, PIC, and TSS

Global Descriptor Table

The bootloader initially defines six selectors: null (0x00), kernel code (0x08), kernel data (0x10), user code (0x18), user data (0x20), and TSS (0x28). The kernel later rebuilds an equivalent flat GDT in src/arch/idt.c, including the runtime address of its TSS.

Interrupt Descriptor Table

VectorSourceHandler
0x20PIT / IRQ0Timer tick and EOI.
0x21Keyboard / IRQ1Scancode buffering.
0x2EATA / IRQ14ATA completion status.
0x80Software syscallRing 3-callable gate, attributes 0xEE.

The PIC is remapped to vectors 0x20–0x2F. The TSS supplies SS0=0x10 and ESP0=0x90000 when privilege transitions return to the kernel.

Exception handling gap: CPU exception gates are not installed. A divide error, invalid opcode, general protection fault, or page fault can therefore escalate into a triple fault and reset the virtual machine.

6. Ring 3 and syscall smoke test

create_test_user_app() constructs a tiny program directly in memory:

mov eax, 1              ; syscall number: print string
mov ebx, 0x00500064     ; pointer to message at app + 100
int 0x80
jmp $                   ; safe user-mode idle loop

enter_usermode() loads user data selectors and builds the five-word iretd frame: user SS, user ESP, EFLAGS with IF set, user CS, and user EIP. The CPU then begins execution at CPL 3.

NumberOperationArguments / result
1Print stringEBX points to a NUL-terminated string.
2Read keyboardReturns a queued ASCII character or blocks while polling the keyboard controller.
3Free memoryEBX=pointer.
4Allocate memoryEBX=size; pointer returned in EAX.

The syscall handler saves registers, switches to kernel data segments, dispatches in C, restores state, and returns with iretd. The test application does not return to a scheduler or shell; it remains in its loop while timer interrupts continue to run.

8. RisottOS Filesystem (RFS)

RFS starts at absolute LBA 100 and stores fixed-size metadata on 512-byte sectors.

Relative areaContents
0512-byte superblock with magic RFS1, layout, and free-space data.
1 onwardAllocation bitmap.
After bitmap16-sector table containing up to 128 file/directory entries.
After tableContiguous file data sectors.

The implementation supports formatting, mounting, directory creation and deletion, file creation, replacement, reading, sizing, deletion, listing, and free-space reporting. Each entry is 64 bytes. The filesystem is non-reentrant, has no journaling, requires contiguous allocation, and is not mounted by the current kmain() path.

9. Shell and build system

Shell

init.c contains commands for screen clearing, echo, RTC access, sleep, ATA tests and raw sector access, graphics demos, memory operations, and RFS operations. It also protects low disk sectors from raw writes. The shell is currently unreachable because kmain() launches the Ring 3 smoke test instead of launching /init.bin through the Ring 3 syscall interface.

10. Known risks and next steps

  1. Complete paging isolation: create separate kernel and user mappings, guard the stack, and validate user pointers before syscall access.
  2. Replace fixed addresses: derive kernel size, stack placement, heap bounds, and user image placement from a memory layout rather than hard-coded constants.
  3. Build a scheduler boundary: define process state, user return policy, and a controlled path back from the test application.
  4. Harden interrupts and drivers: validate ATA controller state and make interrupt-shared data access explicit. Keyboard IRQ acknowledgement now has one owner.
  5. Re-enable the shell intentionally: mount or format RFS safely during startup and choose whether the shell or Ring 3 demo is the primary boot target.
  6. Improve RFS durability: add allocation strategy, metadata ordering, recovery, and fragmentation handling.
Engineering perspective: RisottOS has crossed the important boundary from a protected-mode kernel into a working privilege-level transition. The next milestone is not more Ring 3 instructions; it is isolation, fault reporting, and a controlled execution model around them.
